# Задание: настройка ТЖ из base_list (как показатели в 1С-Мониторе)

Делать после `analysis-forms.md`, отдельной веткой `tj-settings`, один PR, по-русски. Эталон logcfg Монитора — `monitor-logcfg-ref.md`.

Пользователь в base_list отмечает для базы показатели — base_list сам формирует logcfg.xml для сервера, как Монитор.

1. Регистр `рбфНастройкиТЖ`: Сервер1С (ссылка как в СерверыИБазы) + ИмяБазы1С → флажки и пороги показателей:
   ДолгийЗапрос (порог, с), ОжиданиеНаБлокировке (1С / СУБД), Взаимоблокировка (1С / СУБД), ОшибкаТЖ, Транзакции, СерверныйВызов (порог), ДампПроцесса (на уровне сервера), КаталогЛогов, Глубина (часы).
2. Форма «Настройка ТЖ» в разделе «Анализ»: дерево Сервер → Кластер → База (из СерверыИБазы), справа список показателей с флажками и индикатором, внизу настройки выбранного показателя — компоновка как у Монитора («Настройка мониторинга»).
3. Функция `ПравилаРеестраБаз.СформироватьLogcfg(Сервер)` → текст XML: по каждой базе с включёнными показателями отдельные log-каталоги `<Каталог>\<база>_<порт>\Queries|Transactions|1C_Locks|SQL_Locks|1C_Deadlocks|Exceptions`, фильтр p:processName, только нужные свойства, `<dbmslocks/>` при блокировках СУБД (точный состав — `monitor-logcfg-ref.md`). Взаимоблокировка требует ОжиданиеНаБлокировке — проверка при записи.
4. Применение: кнопка «Применить на сервере» ставит команду в `ОчередьКоманд` (существующий механизм) «записать logcfg» с текстом; исполнитель на сервере (агент rbf / ОбработчикКомандОбслуживания) делает бэкап текущего `C:\Program Files\1cv8\conf\logcfg.xml` (`logcfg.xml.bak_<дата>`) и пишет новый. Кнопка «Показать logcfg» — просмотр без применения. Предупреждение о росте объёма ТЖ.
5. HTTP `rbf-admin`: GET `logcfg?server=` — текст для агента.
Сдача: PR, что не проверено (EDT и загрузка — локально).
