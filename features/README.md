# Автотесты Vanessa Automation для base_list / РеестрБазФикс

Сценарии гоняются на **боевой** base_list (решение от 23.10.2026). Поэтому:

- каждый сценарий помечается `@readonly`, если ничего не меняет в данных; сценарии с изменениями — только после
  отдельного согласования, с тегом `@writes` и уборкой за собой;
- контекст сценария: `Дано Я открыл новый сеанс TestClient или подключил уже существующий`;
- данные для проверок подбираются запросом к живому реестру в начале сценария, имена баз и людей в тесты не зашиваются.

## Что покрыто

| Каталог | Что проверяет | Сценариев |
|---|---|---|
| `smoke/` | список «Серверы и базы» открывается, кнопки РеестрБазФикс (`рбфКнопка*`) на месте, список не пустой — признак, что набор расширений применился | 1 |
| `interface/` | каждая команда командного интерфейса по разделам (Справочники, Управление БД, Анализ, Архив почты, Администрирование) открывает свою форму с ожидаемым заголовком | 46 |
| `functional/` | отборы реестра; кнопки с записью (временная запись `autotest_vanessa`): «Стать владельцем», «Продлить», отказ «Вернуть базу», «Переместить в архив»; рассылка (тестовый владелец «Автотест Vanessa»); отключение сотрудника (учётка AD `test.vanessa`); «Применить» logcfg, запись настроек мониторинга, пробный прогон ИИ; формирование отчётов | 13 |
| `restore/` | «Вернуть базу» у удалённой правилом базы: очередь команд → RESTORE из бэкапа → регистрация в кластере → реестр снова тестовый, владелец — вернувший. **Не в регрессии** (тег `@restore` исключён в `VAParams.regress.json`), запуск только `run-restore-test.ps1` — он готовит SQL-базу `autotest_restore` и убирает её | 1 |

Карта команд снята с живого командного интерфейса (`manage_command_interface get_all`) 25.10.2026.
Новая команда в интерфейсе — строка в `Примеры:` соответствующего файла `interface/`.

## Сознательно не покрыто

- константы раздела «Справочники → Сервис» (`BLPass`, `PassПрод`, `PassТест`, `УЗПрод`, …): открытие показывает пароли,
  а скриншот ошибки сохранил бы их на диск;
- настоящий «Анализировать» в ИИ-анализе: каждый прогон стоит денег, в регрессии только пробный прогон;
- само удаление базы правилом «Актуальность»/«Владелец»: `restore/` начинает с состояния, которое правило оставляет.
